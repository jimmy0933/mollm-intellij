# MoLLM for IntelliJ — 0.7.0（PR 預覽版）

將使用者提供的 MoLLM VS Code 0.3.11（MIT，yhho）改寫成 IntelliJ 原生外掛。
此版提供 **Chat／Agent 模式與用量儀表板**。

安裝包下載：[GitHub Releases](https://github.com/jimmy0933/mollm-intellij/releases)。目前儲存庫為私人，需登入具有存取權限的 GitHub 帳號。

此分支的 0.7.0 預覽包位於 `artifacts/mollm-intellij-0.7.0.zip`，尚未合併或發布正式 Release。

## 0.7.0：Agent 工具與報告可靠性

- 新增 `list_directory` 列第一層項目與 `find_files` 依名稱搜尋，避免在多專案工作區用內容搜尋猜 repo 名稱。列表及文字搜尋提供 `offset`／`page_size`、`next_offset` 與完整性標記；超過掃描深度／數量、無權限或文字檔大小限制時，不會把不完整的「No matches」宣稱為完整結果。結果分頁會重新掃描，期間檔案異動可能改變排序與位置。
- `read_file` 分辨不存在、是資料夾、過大、二進位與讀取失敗；回傳 `chars`、`next_start_line`、`next_start_column`，可接續長行或被輸出大小限制截斷的文字。
- 工具執行前驗證完整、嚴格 JSON 物件。串流保留 `finish_reason` 與服務提供的 token usage，若為 `length`／`max_tokens`，不執行該回合的工具；缺少用量顯示「未提供」。只在模型宣告支援 `stream_options` 時請求串流用量。IDE 日誌記錄結束原因、數值額度、用量與各工具參數長度，不記錄參數內容、路徑或 API Key；設定「問題排查 → 顯示每輪串流診斷」可在對話顯示。錯誤訊息仍會提供必要診斷。
- 同工具／目標／原因連續失敗兩次，暫停本段、保留完整工具配對與待讀引導訊息，可調整後按「繼續 Agent」。不設限模式仍有此防止無限重試的機制；恢復時重新計算連續失敗次數。
- `append_file` 按小段附加既有檔案，要求 `expected_chars`（正規化換行後的 UTF-16 字元數），檢查確認前後的內容變動；同段於相同位置重試不重複附加。仍遵循一次／目錄永久授權。
- `create_review_report` 以指定專案目錄建立 `mr<編號>-mollm.md`，已有同名檔案採 `-2` 等後綴。若指定子目錄，使用 Agent 工作目錄內最近的 Git repo 根目錄。一般 `create_file` 若使用 `mr51-review.md`／`mr51-claude.md`／`mr51-mollm.md` 等 MR 報告名稱，也會套用命名與同名保留規則；要更新既有報告仍用 `replace_in_file`／`append_file`。
- `check_review_report` 讀取完整報告，檢查磁碟與編輯器內容、命名、標題、Head／Base／測試狀態欄位及可辨识的風險總表數量。Agent 結束時也會自動檢查本次建立的報告，接續執行可從已配對的成功寫檔結果恢復檢查名單。這只驗證儲存與基本結構，不能證明問題已重現、已編譯或已跑測試。
- 每輪補上最近的明確 MR 請求與後續使用者引導作為任務提醒，降低把「只 review 此 repo」誤當成「只找既有報告」的機會；不替代模型對需求的理解。

0.6.4 解除 Agent 讀取／列檔／搜尋的路徑排除規則，支援 `.agent`、`.agents`、`.claude` 等隱藏目錄、產出目錄、專案外絕對或相對路徑，以及符號連結。相對路徑以 Agent 工作目錄為起點；實際存取仍取決於作業系統權限。修改與指令工作目錄的原有邊界不變。

新對話預設使用 **Agent**，仍可切換到 Chat。設定頁新增 **Agent 執行限制 → 不設限（模型回合與工具操作）**；勾選後不會因這兩項額度停止，直到完成、手動停止或請求失敗。選項會保存並於下一次執行或續作生效，取消勾選會恢復原有數值上限。模型 context、服務端額度與單次工具逾時仍適用。

## MR review 上限與接續

舊版固定 20 個模型回合／64 次工具，一個回合可能呼叫多個工具，因此即使顯示 36／64，也可能因 20 回合先滿而中止。

0.6.4 改為每段預設 **80 個模型回合／256 次工具操作**。在設定頁的 **Agent 模型回合上限／Agent 工具操作上限** 分別調整，範圍為 1–200 回合、1–2000 次工具，會保存並於下一次執行或續作生效；調高會增加時間與模型用量。

達到上限會顯示停止原因及實際回合／工具計數，並出現 **繼續 Agent** 按鈕。點選後保留目前歷史與工具結果、取得新一段執行額度，指示 Agent 接續未完成檢查。若輸入框有新的要求，會以該草稿作為續作指示，不覆蓋草稿。切換伺服器／模型／工作目錄或開啟新對話會清空原歷史；對話不寫入磁碟，重啟 IDE 後無法接續舊歷史。

大型 review 建議把 Agent 工作目錄設為對應子專案，避免掃描其他專案。搜尋工具現在可直接指定檔案或資料夾，並提示模型優先讀取變更 diff、針對必要呼叫端與截斷區段補讀。這些提示不保證模型一定遵循；大型對話仍受模型 context 與閘道限制。

## 執行中引導與並行任務

Agent 執行中可繼續輸入文字或貼上截圖，按 **Enter／引導 Agent** 追加指示。訊息排入目前任務，Agent 在目前工具操作完成後讀取；尚未執行的舊工具步驟會略過，依新指示重新規劃。正在執行／等待確認的操作不會因引導自動中斷；需要立即停止時仍按 **停止**。尚未讀取的訊息在停止或失敗後會還原到草稿，不會靜默遺失。佇列最多 16 則訊息、圖片合計 20 MiB。

輸入另一個任務後按 **並行任務**，以目前伺服器、模型與 Agent 工作目錄開啟獨立對話分頁，同時保留原任務執行。最多 4 個分頁，每個分頁有自己的歷史、訊息佇列與停止按鈕；關閉新增的分頁會停止該任務。任務共用專案檔案與已儲存的權限，同檔修改會檢查內容是否改變；並行指令並無檔案隔離，操作相同產出時可選不同子工作目錄。

**設定 → 對話與輸入框字體** 可選系統內已安裝字體、聊天預設或 IDE 預設。選取後立即套用到對話、輸入框與下方的中英文 sample，並顯示實際字體名称；保留字體大小與整體介面縮放。聊天預設在 Windows 優先使用 Segoe UI，並透過 Swing 系統備援顯示中文。無法確認此 Codex 聊天介面的精確字型，故採相近的 Windows 字型而非宣稱完全相同。重啟後保留選擇；缺少自選字體時會使用 IDE 預設。

對話頁底部僅保留 **傳送／停止／新對話／並行任務** 四個按鈕，採自然寬度與緊湊間距，窄視窗會換列。已移除「貼上」與「附加選取內容」按鈕；Ctrl+V／Shift+Insert 與右鍵貼上仍可使用。

把圖片或 UTF-8 文字／程式碼檔案拖到對話內容區或輸入框即可附加，也可拖入編輯器選取文字。檔案拖拉使用複製動作，不會移動或刪除原檔。圖片加入可移除的附件預覽；文字檔內容加入草稿，送出前可編輯。一次最多拖入 8 個檔案，文字單檔最多 1 MB，圖片仍遵循 4 張／20 MiB 的限制；資料夾及無法解碼的檔案會顯示原因。

## 安裝

1. IntelliJ → **Settings → Plugins → 齒輪 → Install Plugin from Disk…**。
2. 從 [v0.5.0 Release](https://github.com/jimmy0933/mollm-intellij/releases/tag/v0.5.0) 下載 `mollm-intellij-0.5.0.zip`，或使用本機的 `build/distributions/mollm-intellij-0.5.0.zip`，不要解壓縮。從舊版更新會保留伺服器與金鑰。
3. 依 IDE 提示重新啟動；開啟專案後，在右側點選 **MoLLM**。
4. 點右上方 **設定 → 新增**，填入名稱、Base URL 與 API Key。
5. 在設定頁點 **重新整理**，切回對話、選模型後即可對話；**Enter** 傳送、**Shift+Enter** 換行（也保留 **Ctrl+Enter** 傳送）。

## 設定與截圖

上方 **全螢幕** 按鈕會將整個 MoLLM 介面移至目前螢幕的獨立無邊框視窗。按 **一般大小**、**Esc** 或 **Alt+F4** 可回到原本工具視窗；設定頁的 **MoLLM 視窗大小** 也能切換。切換沿用同一個介面與對話，保留歷史、草稿、附件、捲動位置與執行中的 Agent。關閉全螢幕視窗會恢復一般大小；關閉專案時也會關閉該視窗。每次開啟專案先使用一般大小。

**設定 → MoLLM 介面縮放** 提供 **75%／100%／125%／150%／175%／200%**，會調整 MoLLM 中的文字、按鈕、表格行高、固定尺寸、圖示與間距，並記住比例。可隨時選 100% 還原；對話字體的 Ctrl＋滾輪設定仍保留，與介面比例一起作用。縮放範圍是 MoLLM 工具視窗與其全螢幕介面，外部 IDE 視窗與確認對話框使用 IDE 原有設定。

在對話內容或輸入框上按住 **Ctrl** 滾動滑鼠滾輪：往上放大、往下縮小文字。兩區一起調整，範圍 10–40，會記住大小；不按 Ctrl 時仍為一般捲動。

**設定 → 使用量更新頻率** 可選 **30 秒／1 分鐘／3 分鐘**，預設 1 分鐘。變更會立即重新安排用量頁與狀態列的更新排程，並保存設定。MoLLM 視窗顯示時自動查詢目前伺服器的用量，對話／Agent 執行中仍可更新；上一個用量請求未完成時會略過該次計時，不堆積請求。模型清單於啟動、切換伺服器或手動重新整理時載入。

右上方 **設定** 按鈕會開啟新的設定頁，集中伺服器選擇／新增／編輯／刪除／重新整理、模型參數、Agent 工作目錄、逾時與思考內容顯示。主畫面保留模型及 Chat／Agent 切換。

截圖後點進對話輸入框，按 **Ctrl+V**，圖片會出現在輸入框上方；可按預覽下方的 **移除**。輸入問題後按 **Enter**，以 **Shift+Enter** 換行，也可直接傳送只有圖片的訊息。多張附件可水平捲動查看。

0.3.1 修正 0.3.0 只安裝 Swing TransferHandler、未提供 IntelliJ PasteProvider 的缺漏：輸入框現在透過 UiDataProvider 提供 IDE 貼上動作，並使用 IntelliJ CopyPasteManager 讀取剪貼簿。Ctrl+V、Shift+Insert、右鍵「貼上文字／截圖」與輸入框旁的「貼上」按鈕使用相同處理。剪貼簿空白、不支援或無法讀取時會在底部顯示原因。

Chat 與 Agent 都會把圖片以 OpenAI 相容的 `image_url` PNG data URI 送出，保留於後續對話與 Agent 工具迴圈中。圖片僅在記憶體處理，不建立截圖暫存檔。一般文字的貼上、剪下與複製仍可使用。

每次最多 **4 張**；單張編碼後 PNG 最多 **10 MiB／1600 萬像素**，合計最多 **20 MiB**。模型與閘道必須支援圖片輸入。若模型明確回報不支援，會保留草稿並提示更換模型；回報不準時可在 **設定 → 模型參數** 勾選「強制嘗試圖片輸入」。能力資料缺少時會直接嘗試傳送，由閘道決定是否接受。

回覆失敗／取消且尚未保留 Agent 歷史時，圖片會還原到草稿供重試；已有 Agent 歷史時保留在該歷史中。處理圖片或傳送期間不能再貼圖片，以免附件混入另一則訊息。

此安裝包最低支援 **IntelliJ IDEA 2025.2.6.3，build `IU-252.28539.97`**，
對應使用者實際正在執行的 `D:\ideaIU-2025.2.6.3.win`，以其 SDK 與 JBR 21 重新編譯。
0.1.1 修正了 0.1.0 誤以另一個 262 安裝目錄建置、導致 252 無法安裝的問題。
建置腳本會檢查 SDK 與最低相容版本的主版號一致，避免再次使用較新的 SDK 編譯。

## 使用 Agent

1. 上方模式選單切換成 **Agent**。
2. 選擇支援 **tool calling／function calling** 的模型。
3. **設定 → Agent 工作目錄** 預設 `.`，代表目前 IntelliJ 專案。若開啟 `D:\git` 這種多專案目錄，可填子專案名稱，例如 `momo-be`，讓檔案工具只處理該子專案。
4. 直接交代任務，例如「找出這個 controller 的錯誤、修正並執行相關測試」，按 **Enter**；**Shift+Enter** 換行。
5. 搜尋與讀檔會自動進行；修改／新增檔案會開啟 **diff 視窗**，檢查後選「允許一次」、「此工作目錄下永遠允許」或「拒絕」。
6. 執行指令會顯示 executable、完整參數、工作目錄與逾時，同樣可選一次／此工作目錄永遠允許／拒絕。確認視窗不會鎖住主視窗，可隨時按 **停止**。
7. 模型收到工具結果後會繼續處理，直到回覆完成或達到操作上限。

如果閘道把支援工具的模型錯報為不支援，可在 **模型參數** 勾選「強制嘗試工具呼叫」。這項覆寫不會替原本不支援工具的模型增加能力。

工具包含 `list_directory`、`find_files`、`list_files`、`read_file`、`search_text`、`replace_in_file`、`create_file`、`append_file`、`create_review_report`、`check_review_report` 與 `run_command`。

### Agent 權限

**允許一次** 僅同意本次操作，不儲存永久規則。**此工作目錄下永遠允許** 會儲存目前 Agent 工作目錄的授權，之後該目錄與子目錄中同類工具不再詢問。檔案修改／新增與指令執行分開授權；允許檔案不會同時允許指令。更換 Agent 工作目錄需單獨授權，預設仍為每次詢問。

**設定 → Agent 權限管理** 可勾選目前工作目錄的兩類永久權限，按「儲存目前目錄權限」套用；也可查看所有已儲存目錄並撤銷選取目錄的永久授權。撤銷立即影響之後的工具操作；已獲准或已套用的操作不會回復。授權保留於重啟後，停止 Agent 仍可取消後續操作。指令永久授權是依工作目錄授權所有指令，執行內容仍具有一般系統權限，工作目錄不是 OS 沙箱。

0.5.0 也為對話輸入框註冊獨立的 IntelliJ Ctrl+V／Shift+Insert 動作，直接呼叫與「貼上」鈕相同的圖片匯入流程，避免 IDE 的一般文字貼上動作攔截快捷鍵。
讀檔會優先使用 IntelliJ 編輯器最新內容（含尚未儲存的修改）；檔案編輯使用 IDE command／Document，套用後儲存，可使用 **Undo** 復原。
確認期間文件內容有變動時，外掛會拒絕套用舊修改，要求模型重新讀取。
同一次任務已拒絕的相同修改或指令，不會再次開啟確認視窗。

讀取、列檔與搜尋支援任意可存取的文字檔路徑（相對或絕對），包含隱藏檔、金鑰副檔名、產出目錄與專案外路徑；目錄掃描跟隨符號連結並略過循環與無法存取的項目。修改檔案仍限選定工作目錄，排除符號連結／外部路徑、隱藏檔、常見金鑰檔案與產出目錄。
指令經你允許後具有一般系統權限：**工作目錄不是作業系統沙箱**，指令仍可影響其他檔案或存取網路。
指令使用已儲存的文件，不會自動儲存你其他的未儲存編輯；指令輸出保留最多 64 KB，回傳模型最多 20,000 字元，單次最長 120 秒。
停止會取消待確認操作並嘗試終止執行中的指令及其子程序；已完成的檔案修改仍保留，操作結果會留在 Agent 歷史中。
每段任務預設 **80 回合／256 次工具操作**，可於設定調整。達上限會顯示是哪個額度先滿並提供「繼續 Agent」；續作保留既有檢查結果。

## 功能

- 多個 OpenAI 相容閘道：新增、編輯、刪除；Base URL 自動補 `/v1`。
- API Key 使用 IntelliJ **Password Safe**；留空保留舊金鑰，可勾選清除。
- `/v1/models` 為授權清單；`/model_group/info` 補充價格、token 上限與能力，排除非 chat 模型。
- 每個伺服器可設定模型白名單；留空自動使用所有可用模型。
- SSE 串流文字、思考內容（引言／混合／隱藏）、停止請求與記憶體中的多輪對話。
- 手動附加編輯器選取內容至草稿；按下傳送前可檢查與修改。
- 可設定輸出上限、模型個別 `reasoning_effort`、`thinking.budget_tokens`；推理參數僅在閘道宣告支援時送出。
- 用量頁以九張資訊卡顯示金鑰名稱、預算使用率／餘額、RPM 上限、TPM 上限、預算重置日、近 30 日消費、請求次數、成功率／失敗次數、Token 合計（如 `202.3M`），並保留逐日圖與逐模型表格。
- 免費模型的逐日圖改用請求次數；每日資料以 UTC 日期計算。
- 用量依設定的 30 秒／1 分鐘／3 分鐘頻率更新；狀態列顯示 `○ MoLLM 50.5%`，80% 轉黃、100% 轉紅；多伺服器顯示最高預算使用率，hover 顯示各伺服器消費／預算，點擊開啟 MoLLM。狀態列在上次請求完成後依設定間隔更新，對話完成或手動刷新後另於 5 秒後更新。
- HTTP 認證錯誤會顯示原因並遮蔽 API Key；管理端點無權限時仍可對話。
- 對話不寫入磁碟，關閉專案即釋放；切換伺服器／模型／模式／Agent 工作目錄會清空歷史。Chat 取消或失敗的回覆不加入下一輪；Agent 則保留已完成的工具操作與取消結果。

## 限制

- 不會把模型註冊到 GitHub Copilot 或 JetBrains AI Assistant 的模型選單。
- 回覆以可選取的純文字顯示，包含 Markdown 原文；尚未提供 Markdown 預覽。
- 尚未提供三語介面、自訂 HTTP headers、完整能力覆寫、輸入 token 精確計算或歷史自動摘要。長對話超出模型 context 時，需另開新對話。
- Chat 的程式碼 context 可透過拖入檔案或選取文字加入草稿；拖入檔案目前讀取已儲存內容。Agent 可自行搜尋／讀取任意可存取的文字檔案，但尚未提供 IntelliJ PSI 符號／參照工具或 MCP 工具。
- 單次讀檔最多 300 行，單檔最多 1 MB；列檔／搜尋最多掃描 20,000 個項目、深度 20 並收集 5,000 個路徑。列表每頁最多 300 個路徑，文字搜尋每頁最多 80 個匹配行；可用回傳的位置繼續下一頁，達掃描上限仍需縮小路徑。搜尋超長行回傳最多 2000 字元的摘錄，完整內容可用 read_file 接續讀取。
- 每日用量讀取最多 1000 筆，若閘道回報多頁則顯示資料不完整的提示。
- 此版未用真實 MoLLM 金鑰連線，也未在 IDE 中完成實際互動驗收；安全儲存的實際行為依 IntelliJ Password Safe 設定。

新版 JetBrains Copilot 本身已有 OpenAI 相容自訂端點功能，若後續需要沿用 Copilot agent，可另以 MoLLM URL／金鑰配置。
參考 [GitHub 官方公告](https://github.blog/changelog/2026-07-14-github-copilot-for-jetbrains-expands-byok-capabilities/)。

## 建置與驗證

不需下載 IDE、額外函式庫或連接閘道。使用已安裝 IntelliJ 的 `lib/*.jar` 作為編譯 SDK，不會把 IDE 函式庫打包進外掛。
需使用可讀取 SDK class 的 JDK；本次 SDK 使用隨附 JBR 21，輸出 Java 21 bytecode。

```powershell
cd D:\git\mollm-intellij
.\build.ps1 -IdeaHome 'D:\ideaIU-2025.2.6.3.win'
```

`build.ps1` 優先使用 IDE 隨附的 javac，也可傳入 `-JdkHome`。
會編譯、執行 loopback HTTP 整合測試、打包 JAR 與可安裝 ZIP；任一檢查失敗即停止。

也可將本專案作為 Gradle 專案開啟，設定 Gradle JVM 為 IDE 隨附 JBR：

```powershell
$env:JAVA_HOME = 'D:\ideaIU-2025.2.6.3.win\jbr'
.\gradlew.bat buildPlugin '-PideaHome=D:\ideaIU-2025.2.6.3.win'
```

本專案使用 Gradle Java plugin 與本機 SDK 路徑，沒有整合 JetBrains Plugin Verifier、Marketplace 發佈或 sandbox `runIde` 工作。

測試涵蓋 URL 正規化、Bearer 認證、模型權限邊界、embedding 排除、參數過濾、輸出上限、UTF-8 分片、LF／CRLF／多行 SSE、兩種推理欄位、管理路由 403、金鑰遮蔽、錯誤／截斷串流、閒置逾時、取消連線、IntelliJ XML 設定保存，以及用量面板 headless 繪製。
